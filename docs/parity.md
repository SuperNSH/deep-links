# Parity with `app_links`, React Navigation linking, and Tauri's deep-link plugin

The `app_links` names come from `.refs/app_links` (pub 7.2.2: `app_links/lib/src/app_links.dart`, `app_links_platform_interface/lib/`, `app_links_web/lib/`). The React Navigation names come from `.refs/react-navigation` (`@react-navigation/native` 8.0.0-alpha.51, `@react-navigation/core` 8.0.0-alpha.41: `packages/native/src/{types,useLinking.native,useLinkTo,useLinkProps,useLinkBuilder,useRoutePath,Link,extractPathFromURL,getStateFromHref}.tsx` and `packages/core/src/{getStateFromPath,getPathFromState,getActionFromState,validatePathConfig,getPatternParts,types}.tsx`). The Tauri names come from `.refs/plugins-workspace/plugins/deep-link` 2.6.3 (`src/{lib,commands,config,error}.rs`, `guest-js/index.ts`). All read on 2026-11-11.

Every row below is a design mapping, not a status claim: the crate exports only `status()` today (`src/lib.rs`). A row's behavior counts only when CI runs its test, in Rust and in TypeScript.

Status words:

- **Ported**: same semantics, edge cases included; only the language changed.
- **Adapted**: same goal, different mechanics, named in the row.
- **Not planned**: no counterpart in the predetermined API; the reason is in the row.

Our names (predetermined; the TypeScript package mirrors them one-to-one): `DeepLinks` (`new(backend, routes)`, `initial()`, `next()`, `stop()`, `pending()`), `Link { url, kind }`, `LinkKind { Universal, App, Custom }`, `RouteTable` (`from_config`, `match`) with `RouteMatch { screen, params }`, `PendingLink` (`hold`/`claim`/`clear`), `DeepLinksError { code, kind, message }` with `ErrorKind`, the `Backend` trait with `FakeBackend` (TS: `memoryBackend()`, plus `rustBackend()` via `nsh-deep-links/native`), the `association` module (`assetlinks_json`, `apple_app_site_association`), and platform modules `{apple, android, windows, linux, web, unsupported}`. Custom schemes are delegated to `nsh_core::url_scheme`; this crate adds the verified-web-link layer.

## `app_links` 7.2.2

| Their API | Ours | Behavior | Why |
|---|---|---|---|
| `AppLinks()` (singleton factory) | `DeepLinks::new(backend, routes)` / `new DeepLinks(backend, routes)` | Adapted. Not a singleton: one explicit instance per app, built from a `Backend` (link source) and a `RouteTable`. The multi-handler bug React Navigation only warns about is structurally impossible here. | A hidden global invites two owners routing one link; one named owner resolves each link once. |
| `getInitialLink() -> Future<Uri?>` | `DeepLinks::initial()` | Ported. The link that started the app, or no link on a plain cold start. Returns a `Link` with its `LinkKind`, not a bare URI. Resolves once: a link, no link, or a coded error. | Same platform fact (the OS hands over one launch link); kind matters because verified links are trusted differently. |
| `getInitialLinkString() -> Future<String?>` | `Link.url` (one form) | Adapted. No parallel string entry; the raw text is `link.url.as_str()` / `link.url.toString()`. | The Dart pair exists for `Uri.tryParse` limits; one parsed URL covers both. |
| `getLatestLink() -> Future<Uri?>` | `DeepLinks::next()` | Adapted. No mutable "latest" query. Links are pulled one at a time and each link resolves exactly one `next()`; a link that arrives with no caller waiting goes to `PendingLink`, not into an overwritten slot. | A "latest" slot can lose a link (overwritten before read) or double-route one (read twice). |
| `getLatestLinkString() -> Future<String?>` | `Link.url` via `next()` | Adapted, same as the row above. | Same as `getInitialLinkString`. |
| `stringLinkStream -> Stream<String>` (broadcast) | `DeepLinks::next()` (await one link) + `DeepLinks::stop()` | Adapted. Pull, not broadcast: no listener registry, no replay to late listeners. `stop()` ends delivery and resolves any outstanding `next()` with a cancel code; nothing hangs. | 7.2.2 replays every pre-listen link to every listener; with `getInitialLink` too, one link can be routed twice. Exactly-once is the repo rule. |
| `uriLinkStream -> Stream<Uri>` (broadcast; malformed URIs dropped silently) | `DeepLinks::next()` yielding `Link` | Adapted. Same position in the API, but a malformed URL resolves its `next()` once with `DeepLinksError` (bad-link code) instead of vanishing between the two streams. | A bad link is an answer, not silence; an operation resolves exactly once. |
| Buffering: "send all links received before the first listen" (7.2.2 changelog) | `PendingLink` (`hold`/`claim`/`clear`) | Adapted. A link that arrives before the app can route it — no `next()` awaited yet, or the login gate is closed — is held in the one pending slot and claimed later; it survives login. It is never replayed to a second consumer. | The hold preserves the link app_links buffers, without the double-delivery a broadcast replay causes. |
| `AppLinksPlatform` + static `instance` getter/setter (platform registry) | `Backend` trait; platform modules `{apple, android, windows, linux, web, unsupported}` | Adapted. The platform seam is a trait implemented by named modules and passed to `DeepLinks::new`; there is no settable global. `FakeBackend` / `memoryBackend()` replace the platform for tests. | Explicit injection is testable and cannot be swapped under a running instance. |
| Method channel `com.llfbandit.app_links/messages` ('getInitialLink', 'getLatestLink') and event channel `.../events` | not applicable — the `Backend` trait is the seam | The bridge transport lives in the platform modules and `nsh-platform-*`; this crate defines the trait and the routing on top. | Org bridge pattern (see `.refs/nsh/crates/nsh-platform-*`). |
| `OnAppLinkFunction = void Function(Uri uri, String stringUri)` | not planned | The two-value callback existed for custom string handling (e.g. uppercase URIs); `Link` carries one parsed URL and a kind. | Nothing in our API needs a second, unparsed copy of the URL. |
| Web implementation (`AppLinksPluginWeb`): initial link is `window.location.href`, streams emit it once | `platform::web` (module name predetermined; behavior follows `docs/decisions.md` item 3) | Adapted, scope open. On web the only incoming link is the page URL at load, exactly as app_links treats it; there are no custom schemes or association files in a browser tab. | Browsers hand a page its URL at load; there is no OS hand-off to a running page. |

## React Navigation linking model (`@react-navigation/native` + core)

| Their API | Ours | Behavior | Why |
|---|---|---|---|
| `NavigationContainer` prop `linking?: LinkingOptions<ParamList>` | `DeepLinks::new(backend, routes)` | Adapted. Linking is not a view-container prop; the app builds one `DeepLinks` from a `Backend` and a `RouteTable` and routes matches itself. React Navigation's dev-mode guard against linking "configured in multiple places" is unnecessary with a single constructed owner. | NSH apps do not run a React Navigation container; ownership must be explicit without one. |
| `LinkingOptions.enabled?: boolean` | not planned as a field: construct, or call `DeepLinks::stop()` | Adapted. Not linking is not constructing; stopping is `stop()`, which also cancels outstanding waits. | A boolean beside live listeners creates half-enabled states that hang or drop silently. |
| `LinkingOptions.prefixes?: LinkingPrefix[]` (formats `myapp://`, `https://host`, `https://*.host`, `https://host/path`, `*`; default `['*']`; stripped before parsing) | `RouteTable` prefixes (via `from_config`) | Ported. Prefixes decide ownership and are stripped before pattern matching, with the same five forms including wildcard hosts and `*`. One difference: a URL that matches no prefix resolves `next()`/`initial()` once with a not-our-link error code, where React Navigation swallows the throw and ignores the URL. | The linking model is ported, not reinvented; but untrusted input gets a coded answer, and the brief requires an allowlist. |
| `LinkingPrefix = '*' \| (string & {})` (type) | prefix values in `RouteTable::from_config` | Ported. The same strings are accepted, validated at construction. | Type-for-type port of the accepted forms. |
| `LinkingOptions.filter?: (url: string) => boolean` (rejected URLs are dropped: `getStateFromHref` throws, `useLinking` catches, nothing routes) | `PendingLink` (`hold`/`claim`/`clear`) | Adapted. No drop-filter. A link that must not route yet — the canonical case is an auth callback — is held in the pending slot and claimed after login; it survives login instead of being discarded. | The filter's own doc example is expo-auth-session URLs; dropping them loses the link a login flow needs. |
| `LinkingOptions.config.path?: string` (root path prefix; params forbidden in it) | root path prefix in `RouteTable::from_config` | Ported. Prepended to every screen pattern, must be param-free, rejected at construction otherwise (React Navigation throws at parse time). | Same tree shape, validated earlier. |
| `LinkingOptions.config.screens: PathConfigMap<ParamList>` (and nested `PathConfig.screens`) | pattern-to-screen config in `RouteTable::from_config` | Ported. Screen names map to patterns, nested `screens` compose parent paths, unknown or malformed fields are a construction error. | Core of the ported linking model. |
| `LinkingOptions.config.initialRouteName?: string` (and nested `PathConfig.initialRouteName`) | not planned | A flat `RouteMatch` names the matched leaf screen; React Navigation needs `initialRouteName` only to assemble the chain of ancestor routes in a nested navigation state, which this crate does not build. The app decides what surrounds the matched screen. | Wrap, never rebuild: no nested state object exists here to inject ancestors into. |
| `LinkingOptions.getInitialURL?: () => string \| null \| Promise<...>` (default `Linking.getInitialURL()` raced against a 150 ms timeout, a workaround for facebook/react-native#25675) | `Backend` (the injected link source) behind `DeepLinks::initial()` | Adapted. Same role: the cold-start link comes from the platform through the `Backend` trait. The fixed 150 ms race is not part of our API; a backend that can hang is a backend bug, and `initial()` still resolves exactly once (link, no link, or coded error). | The race papers over one React Native core bug; a backend seam lets each platform solve it instead of every user re-racing it. |
| `LinkingOptions.subscribe?: (listener) => unsubscribe` (default `Linking.addEventListener('url')`) | `Backend` event feed + `DeepLinks::next()` / `stop()` | Adapted. Same seam — where runtime links arrive — but delivery is pull: each link resolves one `next()`, and `stop()` is the unsubscribe that also cancels outstanding waits. | Callback registries plus broadcast delivery are what the exactly-once rule forbids. |
| `LinkingOptions.getStateFromPath?: typeof getStateFromPath` (per-call parser override) | not planned | The parser is `RouteTable::match`, fixed and validated at `from_config`; there is no per-call override hook. A table that needs a custom parser is a table that failed construction. | Overrides exist because the config is an untyped object; ours is typed and checked once. |
| `LinkingOptions.getPathFromState?: typeof getPathFromState` (web only) | not planned | URL generation (state to path) has no counterpart; `RouteTable` maps URL to screen only. | There is no navigation-state object to serialize and no web history to sync in this crate. |
| `LinkingOptions.getActionFromState?: typeof getActionFromState` | not planned | Building NAVIGATE/RESET actions is React Navigation's state machine; we stop at `RouteMatch { screen, params }`. | Wrap, never rebuild. |
| `getStateFromPath(path, options?, previous?) -> PartialState<NavigationState> \| undefined` (exported; internal helpers `extractPathFromURL`, `getStateFromHref` feed it) | `RouteTable::match(path) -> RouteMatch { screen, params }` | Ported rules, adapted output. Specificity order (static > param with regex > param > one-or-more > zero-or-more > wildcard), query params merged with same-named path params winning, percent-encoded segments matched then decoded and regex-checked, `//` and trailing `/` normalized, empty path matching a `path: ''` screen. Output is one flat `RouteMatch`, not a nested state; parse failures are a coded error, not `undefined`. The config-less fallback (path segments become route names) is not planned: a table with no patterns fails `from_config`. | Untrusted input must hit an explicit, validated allowlist (brief); a silent `undefined` hides a malformed link. |
| `getPathFromState(state, options?) -> string` (exported) | not planned | Reverse direction (state to URL). | No state model to serialize; adding one would rebuild React Navigation. |
| `getActionFromState(state, options?) -> NavigateAction \| Action \| undefined` (exported) | not planned | Action construction for a foreign navigator model. | Same as `LinkingOptions.getActionFromState`. |
| `validatePathConfig(config, root?)` (exported; also run by `NavigationContainer`) | `RouteTable::from_config` (validation) | Ported. Rejects the three things the reference rejects here — extraneous keys, wrong value types, params in the root `path` — at construction, in Rust and TypeScript, as `DeepLinksError` with a config error code. The alias-without-path rule is enforced elsewhere in the reference; see the `PathConfig.alias` row. | Same checks, moved from link time (or mount time) to construction time. |
| `PathConfig.path` pattern syntax: `:param`, optional `:param?`, repeats `:param+` / `:param*`, inline regex `:param(\d+)`, wildcard `*` (via `getPatternParts`) | pattern strings in `RouteTable` screen config | Ported. The same pattern grammar, parsed by the same rules (modifiers cannot combine, `:` mid-segment is an error), with the same sort ranking. | The grammar is the linking model; inventing a second one would break parity tests. |
| `PathConfig.parse` (per-param function or Standard Schema V1; a failed schema invalidates the whole match) | inline regex in the pattern (`:id(\d+)`); decoded params in `RouteMatch.params` | Adapted. Function- and schema-valued parsers are not carried across the bridge; the table expresses what a pattern can express, and the app validates decoded params itself. A regex mismatch rejects the pattern, as in React Navigation. | Rust/TS parity law: the same config must behave the same in both languages; function values in config do not survive that. |
| `PathConfig.stringify` (per-param to-string for URL building) | not planned | URL building is not in the API. | Follows `getPathFromState` being not planned. |
| `PathConfig.alias: (string \| PathConfigAlias)[]` (extra patterns for the same screen; ordered after the main pattern) | alias patterns in `RouteTable` screen config | Ported for string aliases: extra patterns resolving to the same screen, matched after the main pattern unless more specific. An `alias` on a screen with no `path` is rejected: React Navigation throws that at match time, while normalizing configs inside `getStateFromPath` (`getStateFromPath.tsx`), not in `validatePathConfig`; ours fails `from_config` construction with a config error. `PathConfigAlias`'s `parse` follows the `parse` row; its `shared` follows the `shared` row; `exact` is ported. | Aliases are data; they cross the bridge unchanged. |
| `PathConfig.exact?: boolean` (ignore parent path segments) | exact flag on a screen pattern | Ported. | Plain data flag, same effect on composition. |
| `PathConfig.shared?: boolean` (one pattern may resolve to screens in multiple navigators; disambiguated against the live state and initial routes) | not planned | Disambiguation needs a previous navigation state; a flat `RouteMatch` has no navigators to choose between. A pattern that would resolve to two screens fails `from_config`, as React Navigation throws for non-shared duplicates. | The ambiguity `shared` resolves cannot be expressed in one flat match. |
| `useLinkTo() -> linkTo(href)` | `RouteTable::match` (parse half); dispatch is the app's | Adapted. Parsing an arbitrary href to a screen is the table's job; there is no navigation object to dispatch into. | This crate routes links; it is not a navigation store. |
| `useLinkProps({ in?, screen, params?, action?, href? }) -> { href, role, onPress }` | not planned | A UI hook for anchor rendering and press handling. Apps that want anchors build them on `RouteTable` and their own press code. | The TS package mirrors the data API (`DeepLinks`, `Link`, `RouteTable`, ...), not React components. |
| `useLinkBuilder() -> { buildHref(name, params?), buildAction(href) }` | `buildAction`'s parse half is `RouteTable::match`; `buildHref` not planned | Adapted on one half only. href-to-screen is ours; screen-to-href is not (see `getPathFromState`). | Same split as `getStateFromPath` vs `getPathFromState`. |
| `useRoutePath() -> string \| undefined` (path of the current route) | not planned | Current-path tracking exists to keep a URL bar in sync on web. | No web history sync in this crate. |
| `useStateForPath() -> FocusedRouteState \| undefined` (core hook; doc: the state "can be used with `getPathFromState` to build a path") | not planned | Exists only to feed the URL-building half: `useRoutePath` and `useLinkBuilder`'s `buildHref` are thin wrappers over it. With no state model to serialize, there is nothing to feed a path builder. | Same as `getPathFromState`: wrap, never rebuild. |
| `Link` component (`in`, `screen`, `params`, `href`, `action` props) | not planned | A rendered anchor component. | Not a UI kit; same reason as `useLinkProps`. |
| `LinkingContext` (React context carrying linking options) | not planned | Options are explicit arguments (`DeepLinks::new(backend, routes)`); there is no context tree to thread them through. | The crate is framework-agnostic Rust plus a thin TS mirror. |

## Deliberate differences, stated plainly

- **Pull, exactly once, not broadcast.** app_links exposes broadcast streams (replaying pre-listen links to every listener) plus initial/latest queries; Tauri exposes a callback registry over a global event. Ours resolves each link through exactly one `next()`, and `stop()` cancels outstanding waits. Reason: the repo rule that an operation resolves exactly once, and the double-routing bug class both references guard against.
- **`PendingLink` instead of buffering or filtering.** app_links replays buffered links; React Navigation's `filter` drops rejected URLs (its own example: auth callbacks). Ours holds the one pending link and lets the app claim it after login. Reason: the brief's login case — the auth link must survive, not be re-delivered nor lost.
- **Validated, typed `RouteTable` instead of an untyped config with per-call overrides.** `from_config` rejects everything `validatePathConfig` rejects, at construction, in both languages. Reason: the parity law needs one config shape with one behavior; runtime overrides only exist to patch an untyped config.
- **We stop at `RouteMatch`.** No nested navigation state, no NAVIGATE/RESET actions, no URL building (`getPathFromState`, `buildHref`, `useRoutePath`, `useStateForPath` are not planned). Reason: wrap, never rebuild React Navigation.
- **Runtime scheme registration is not planned.** Tauri writes the Windows registry and Linux desktop files at runtime; NSH apps declare schemes and entitlements in the manifest at build time, and this crate instead builds and validates the association files. Reason: the trust chain for verified web links lives in the bundle and on the web server, not in per-run registry writes.
